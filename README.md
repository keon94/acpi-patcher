# ACPI Table Patcher

This repository provides a small, reversible workflow for experimenting with
ACPI table additions and overrides on Linux.

The tooling is generic, however assumes a Fedora-like layout and ecosystem. It is not inherently tied to any hardware, however at the time of creation it was for Lenovo and NVIDIA (on Fedora 44).

The contents of `acpi/` and `patches/` are intentionally ignored by Git.
They are machine-specific inputs and must be created locally for each target
machine. The scripts are tracked; firmware dumps and patch sources are not.

## What this does

The project has two scripts:

### `dump-acpi.sh`

Captures the ACPI tables currently exposed by the running kernel:

```text
acpi/raw/       Original binary ACPI tables
acpi/dsl/       iasl-decompiled ASL sources
acpi/.manifest  Files generated by the dump script
```

Run it before creating a patch:

```bash
./dump-acpi.sh
```

The script preserves raw `FACS` data but skips decompiling it because FACS is
not an AML namespace. It does not modify `patches/`.

The dump is only a baseline. It does not automatically produce a working
patch.

### `acpi-fixes.sh`

Compiles every `patches/*.dsl` file in deterministic `LC_ALL=C` lexical order.
Each source file produces a correspondingly named AML file:

```text
patches/00-base.dsl       -> build/acpi-fixes/00-base.aml
patches/10-nvd1-alias.dsl -> build/acpi-fixes/10-nvd1-alias.aml
```

The generated AML files are installed under `/etc/acpi-tables/`. A dracut
configuration makes them part of every future initramfs:

```text
/etc/acpi-tables/*.aml
/etc/dracut.conf.d/90-acpi-fixes.conf
```

The script also ensures the kernel argument `acpi_table_upgrade` is present in
existing and future Fedora boot entries.

## Important distinction

The DSL files are not text patches applied directly to `DSDT.dsl` or an SSDT.
Each DSL file is compiled into an independent AML table, normally an SSDT,
which the kernel loads from the initramfs during boot.

This means the framework can support many kinds of ACPI experiments, but the
correct AML implementation depends on the target firmware and namespace.

## Requirements

Fedora packages:

```bash
sudo dnf install acpica-tools dracut grubby
```

The running kernel must support ACPI table upgrades:

```bash
grep CONFIG_ACPI_TABLE_UPGRADE /boot/config-$(uname -r)
```

Expected:

```text
CONFIG_ACPI_TABLE_UPGRADE=y
```

## Typical workflow

### 1. Capture the firmware tables

Run on the target machine:

```bash
cd <repo-directory>
./dump-acpi.sh
```

Review the decompiled tables:

```bash
less acpi/dsl/DSDT.dsl
less acpi/dsl/SSDT7.dsl
```

The exact SSDT number varies by machine; inspect the directory rather than
assuming a fixed table name.

### 2. Create a patch

Create one or more `.dsl` files under `patches/`, either manually or with the
help of an AI assistant. The patch must be written in ACPI Source Language and
must match the target machine's namespace and firmware behavior. For example:

```text
patches/00-common.dsl
patches/10-device-fix.dsl
patches/20-power-fix.dsl
```

Every `.dsl` file must compile independently with `iasl`.

### 3. Compile and install the patch set

Run the script as the normal user; it invokes `sudo` only for system changes:

```bash
./acpi-fixes.sh install
```

This will:

1. Discover `patches/*.dsl` in deterministic lexical order.
2. Compile every DSL file with `iasl` before changing system files.
3. Install the AML set and an ownership manifest.
4. Configure dracut for ACPI table inclusion.
5. Add `acpi_table_upgrade` to current and future boot entries.
6. Regenerate all installed initramfs images.
7. Verify that the current initramfs contains every generated AML.

Check the result:

```bash
./acpi-fixes.sh status
sudo journalctl -k -b --no-pager | grep -Ei 'ACPI|table upgrade|SSDT'
```

### 4. Reboot and test

Reboot normally. The standard Fedora kernel entry should be used; no separate
custom BLS entry or custom initramfs is required.

After reboot, confirm the boot argument:

```bash
cat /proc/cmdline
```

It should contain:

```text
acpi_table_upgrade
```

## Rollback

To remove the persistent ACPI patch set:

```bash
./acpi-fixes.sh remove
```

This removes the managed AML files and dracut configuration, removes the
kernel argument, regenerates initramfs images, and leaves unrelated files
alone. Old experimental BLS entries and custom initramfs images are not deleted
automatically; remove those separately after the normal entry has been tested.

## Rollback on boot failure (IMPORTANT)
If an ACPI patch produces an unbootable initramfs, select an older working Fedora kernel or rescue entry from the bootloader and boot it; then run sudo ./acpi-fixes.sh remove from the repository to remove the AMLs, dracut configuration, and acpi_table_upgrade, and regenerate the initramfs images. If no kernel boots, use Fedora’s live/rescue environment, mount the Fedora root and EFI filesystems, chroot into the installation, remove /etc/dracut.conf.d/90-acpi-fixes.conf and /etc/acpi-tables/.acpi-fixes-manifest plus the listed AML files, remove acpi_table_upgrade from /etc/kernel/cmdline, and run dracut --regenerate-all --force before rebooting.

## Repository layout

```text
.
├── acpi-fixes.sh
├── dump-acpi.sh
├── acpi/
│   ├── raw/
│   └── dsl/
├── build/
│   └── acpi-fixes/
└── patches/
    └── *.dsl
```

The `acpi/` and `patches/` contents are local and ignored by Git. The scripts
and patch framework are generic, while the contents of `patches/` describe the
actual firmware fix being attempted.
